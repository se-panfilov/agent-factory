## Implemented behavior (P11 scope only)

1. Added **S11 stage** with `observe → plan → apply → verify`:
   - backup + integrity verification
   - AI-free health snapshot
   - emergency inventory artifact

2. Added **backup create/verify** operations:
   - Level1 allowlist (`state/**`, `deployment-manifest.json`, `policy-level1.json`)
   - explicit auth exclusion
   - temp backup + hash verification + atomic publish
   - retention 14 days for owned backups while preserving latest known-good
   - no deletion of old good backup on failed create

3. Added **service DB backup/verify** path:
   - SQLite `.backup`
   - SQLite integrity check
   - missing app service capability/commands => explicit blocker (`exit 5`) + manual next action

4. Added **safe restore** operation:
   - requires `--backup-id` and `--plan`
   - verifies backup before restore
   - restores through staging
   - preserves `PAUSED`
   - preserves unknown usage semantics (`unknown_usage=true`, consumed count not reduced)
   - never restores/copies auth directory

5. Added **emergency cancellation** (`cancel --emergency`):
   - does not require installation lock
   - writes durable `PAUSED`
   - runs known stop command from manifest
   - stops only containers proven owned by installation label; foreign containers skipped
   - missing stop capability => explicit blocker + manual runbook action

6. Added S11 CLI surface:
   - `backup create`
   - `backup verify`
   - `restore`

7. Added S11 docs:
   - runbook for SSH/VPS/reboot recovery flow
   - backup/health/restore/emergency behavior and constraints

## Failure cases covered

- backup excludes auth/credentials from payload
- restore preserves PAUSED and unknown usage
- SQLite busy/ENOSPC failure does not remove previous good backup
- emergency cancellation while lock exists still performs owned-only stop and does not create normal cancel request
- integrity/hash mismatch and missing backup payload are explicit failures
- service DB backup blocked when app capabilities/commands are absent

## Security-sensitive diff

- no broad deletion/prune; retention constrained to owned S11 backups
- no auth backup copy
- emergency stop checks ownership label before container stop
- restore keeps PAUSED and unknown usage markers, no implicit unpause
- all process execution remains argv-based (`shell=false`) through process adapter

## Remaining blockers / capability boundaries

- Service-specific backup/restore requires app capability evidence; missing capability is blocked by design.
- External heartbeat is optional/degraded-only; no fake healthy state when offline.
- VM/live qualification remains outside offline integration tests.
