# M0.2 — Supervised read-only Scout Runner

## Scope

Реализован только application milestone **M0.2** (PR 1 из guide), без перехода к PR 2 и без installer logic.

Изменения сделаны в `app/m0-02-runner`:

- `make-schemas.ts` — генератор 4 role JSON Schema (A1).
- `runner.ts` — supervised read-only Scout Runner (A2) с командами `run|status|stop|inspect`.
- `verify.mjs` — безопасная fixture-проверка без реального Docker/Codex login (A3).
- `schemas/*.json` — сгенерированные схемы.

`setup/` не менялся.

## Что реализовано

- **Codex CLI в Docker worker** с owner-controlled запуском и одним активным run (`active.lock` + проверка residual контейнеров до старта).
- **run ID + input SHA**: run получает UUID, SHA фиксируется из `git rev-parse HEAD`, записывается в status/provider artifacts.
- **JSON Schema/Ajv validation**: результат принимается только если проходит `schemas/scout.json` и совпадает `task_id`/`input_sha`.
- **stop/status/inspect**:
  - `status` показывает paused/active и историю run-статусов;
  - `stop` ставит PAUSED и удаляет контейнеры runner по label;
  - `inspect [run_id]` показывает lock/residual containers + статус и provider artifact по run.
- **timeout + bounded logs/results**:
  - процесс ограничен `timeout`;
  - общий лимит raw лог-потока (`log_limit_bytes`);
  - лимит размера `result.json` (`result_limit_bytes`);
  - лимиты размера writable `/out` и credential dir `/auth` (`out_limit_bytes`, `auth_limit_bytes`).
- **termination + verified cleanup**:
  - при stop/timeout/interruption выполняется `docker rm -f`;
  - cleanup считается успешным только после residual-проверки по run label/name;
  - при cleanup failure run блокируется, выставляется PAUSED, lock сохраняется для ручного recovery.
- **one LLM, no retries, fail-closed**:
  - второй активный запуск блокируется;
  - автоматических retry нет;
  - неизвестная usage (`usage_unknown`) переводит run в `blocked`.
- **F15 hardening**:
  - raw stdout/stderr сохраняется в redacted-виде (token/bearer/JWT/PEM scrub);
  - `result.json` читается после завершения writer и подтверждённого container cleanup;
  - чтение результата symlink-safe (`lstat`, `realpath` confinement, `O_NOFOLLOW`).
- **Credential isolation / runner restrictions**:
  - worker не получает Docker socket, host home, GitHub write token env;
  - mount-и ограничены `/workspace` (read-only), `/schema.json` (read-only), `/auth` (read-only), `/out`;
  - без privileged/host network/public ports.

## Фактические проверки

Выполнено локально (без реального Docker/Codex):

1. `cd app/m0-02-runner && node --experimental-strip-types make-schemas.ts` — успешно.
2. `cd app/m0-02-runner && npx tsc --noEmit --module nodenext --target es2022 --types node runner.ts make-schemas.ts` — успешно.
3. `cd app/m0-02-runner && node verify.mjs` — успешно (`verify.mjs: PASS`).

Покрытые fixture-негативы:

- wrong SHA
- invalid JSON
- missing result
- extra field schema violation
- timeout
- provider protocol failure
- nonzero exit
- unknown usage (fail-closed)
- cleanup_failed / residual container
- stop/status/inspect path
- daily run cap

## NOT RUN (честно)

- Реальный Docker smoke с настоящими контейнерами.
- Реальный Codex login/OAuth/device flow.
- Реальный запуск `codex exec` против модели.
- Любые GitHub write/publish действия.
- VM/VPS интеграционные прогоны.

## Security-sensitive изменения

- Добавлены redaction и fail-closed ветки для usage/protocol/cleanup.
- Добавлена symlink-safe модель чтения результата.
- Добавлен residual container check как hard gate перед приёмкой результата.
- Добавлены явные ограничения worker runtime (no host home/socket/GitHub write env).
