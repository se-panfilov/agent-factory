## Implemented behavior (P02 scope)

1. **Core CLI contract for S01 path**
   - Implemented commands: `init`, `preflight`, `plan`, `apply`, `status`, `resume`, `verify`, `gate list`, `gate approve`, `cancel`, `recover`.
   - `--config PATH` required by CLI for all runtime commands (except `--help/--version`).
   - One JSON envelope in stdout; operational hints/errors mapped to C03 exit codes.
   - Unsupported command/stage surfaces structured blocked/unsupported errors (not fake success).

2. **Deterministic state/plan engine**
   - Stage closure with prerequisite traversal and cycle detection.
   - Hash-bound plan (`desired_hash`/`plan_hash`) with stale-plan invalidation on config drift.
   - Intent event written before effect; receipt event written after effect.
   - `apply/resume` re-observe before using recorded state; verified checkpoint is not blindly trusted.

3. **State persistence and crash-safety primitives**
   - Atomic write path with temp file, fsync(file), rename, fsync(parent) for state/plan/cancel artifacts.
   - Previous state generation preserved as `state.json.previous`.
   - Event JSONL with per-record checksum/sequence.
   - Torn final JSONL record is quarantined as tail fragment, not trusted.

4. **Locking, duplicate invocation and lock recovery**
   - Installation lock uses `mkdir` ownership record with `boot_id + pid + process_start_ticks + nonce`.
   - Duplicate active invocation returns exit 7.
   - Stale lock during normal apply returns lock error (no auto-delete).
   - `recover --lock-only` quarantines stale lock after liveness checks.
   - `cancel` uses separate atomic cancellation request path.

5. **Typed errors + injectable adapters**
   - `SetupError` typed model: public code/message/next_action/retryable/evidence.
   - Injectable adapters for filesystem/process/http/clock enable deterministic tests.
   - Process adapter enforces trusted absolute binaries and `shell=false`; bounded output + basic secret scrubbing.
   - HTTP adapter implements bounded GET retries (up to 3 attempts, retry-after cap).

6. **S01 preflight stage**
   - Implemented read-only preflight stage module with observe/plan/apply/verify/recover API.
   - Reports host checks for OS/arch/UID/systemd/cgroup/resource sizing signals.
   - No host install/mutation in preflight stage.
