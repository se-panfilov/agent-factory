## Implemented behavior (P09 scope)

1. **Added S09 stage implementation (`setup/src/stages/project.ts`)**
   - Added `S09` stage with dependency `S08`, `observe → plan → apply → verify → recover`.
   - Enforced exact SHA binding from config (`release.source_commit`, strict 40-hex) and target repository selection:
     - default `se-panfilov/anarchy-engine` when allowlist is empty;
     - otherwise first allowlist repository.
   - Added allowlist enforcement and explicit blocker errors when target repo is not approved.
   - Added local detached checkout preparation in isolated cache paths:
     - `.../s09-project/<repo>/<sha>/checkout`
     - `.../s09-project/<repo>/<sha>/checker`
   - Added checkout validation invariants:
     - `.git` present,
     - detached HEAD required,
     - clean tree required,
     - HEAD equals planned SHA.
   - Added read-only target inventory recording (data only, no JS execution):
     - `.nvmrc` value,
     - lockfile kind/hash (`package-lock/pnpm/yarn/none`),
     - package workspaces,
     - `AGENTS.md` presence,
     - `.github/workflows/*` hashes,
     - Playwright config file paths.
   - Added proposal generation artifacts (no GitHub write):
     - baseline workflow proposal,
     - dependabot proposal,
     - metadata JSON with generated paths.
   - Added baseline recorder that separates owner note from collector evidence and maps CI states:
     - `passed -> pass`,
     - `failed -> fail`,
     - `draft/skipped/missing -> unknown`.
   - Added optional PR4 checker hook via adapter contract; default node adapter returns `supported=false` and does not require auth.

2. **Wired S09 into static stage registry**
   - Registered `createProjectStage(...)` in `setup/src/core/engine.ts` after S08.

3. **Added GitHub proposal templates**

4. **Added beginner-friendly manual UI guide**

     - issue creation,

## Failure scenarios covered by fixture tests

- target repository outside allowlist -> blocked with explicit next action;
- baseline recorder maps `draft` and `skipped` CI to `unknown` (never pass);
- detached checkout + SHA-bound inventory/proposal generation success path;
- optional checker path is invoked through fake adapter but does not require auth.

## Security-sensitive diff summary

- No stage code performs GitHub write operations.
- Checkout is immutable-by-SHA and detached; dirty checkout is rejected.
- Inventory reads repository files as plain data and does not execute JS configs.
- CI state classification prevents false positive `pass` when evidence is missing/skipped/draft.

## Remaining blockers / limitations

- Node adapter uses unauthenticated read-only git flow and may block private repositories without separately reviewed read-only credentials.
- PR4 checker is readiness-only in this scope; default adapter reports unsupported.
- Baseline CI proof still requires human-run workflow and explicit evidence file creation.
