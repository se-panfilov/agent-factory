## Implemented behavior (P13 scope only)

1. Added **S13 optional stage** (`dependencies: ["S09"]`) with `observe → plan → apply → verify → recover`.
2. Added validated **platform request input** (`s13-platform-request.json`) with:
   - full candidate SHA,
   - `guard|browser_smoke` profile,
   - unique platform enum entries (max 3),
   - trusted workflow SHA/path + producer identity,
   - owner-reviewed Actions allowance + billing flags.
3. Added mandatory **PR12 browser_smoke adapter requirement**:
   - `s13-browser-smoke-adapter.json` required for `browser_smoke`,
   - missing adapter fails nonzero (`exit 5`, `s13_browser_smoke_adapter_missing`),
   - no success-shaped fallback.
4. Added pinned **workflow proposal template** and validation:
   - fixed labels: `ubuntu-24.04`, `windows-2025`, `macos-15`,
   - pinned `actions/checkout` and `actions/setup-node` SHAs,
   - `permissions: contents: read`,
   - `persist-credentials: false`,
   - duplicate-platform guard and matrix bound ≤3.
5. S13 apply writes **proposal artifacts only** (no auto-dispatch):
   - `s13-proposals/factory-platform-check.proposed.yml`,
   - `s13-platform-readiness.json`,
   - `s13-platform-receipt.json`.
6. S13 verify optionally validates collector evidence from
   `s13-platform-collector-evidence.json`:
   - trusted producer/workflow ref (path+sha),
   - exact candidate and actual checkout SHA,
   - runner label + `RUNNER_OS` + `RUNNER_ARCH` per platform.
7. Missing checks / unimplemented collector are represented as
   `checks_status=unknown`, `integration_verified=false` (no false “pass” claim).

## Failure/error scenarios covered in fixtures

- missing PR12 browser_smoke adapter blocks `browser_smoke` request,
- duplicate platform request entries rejected before proposal generation,
- collector evidence accepted only with trusted workflow SHA/producer + exact runner identity,
- invalid/untrusted workflow ref and runner arch drift rejected,
- docs-only (`platforms: []`) readiness path does not trigger dispatch and stays `unknown`.

## Security-sensitive diff

- S13 does not dispatch workflows or perform GitHub writes.
- Workflow template is read-only permissions and disallows secret-based execution paths.
- Trusted workflow identity (`path@sha`) and producer identity are verified separately from candidate SHA.
- No broad shell execution; adapter command metadata is validated as safe argv only.
