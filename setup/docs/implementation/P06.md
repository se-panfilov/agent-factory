## Implemented behavior (P06 scope)

1. **Added S05 stage implementation (`setup/src/stages/application.ts`)**
   - Added stage registration model for S05 with dependency on S04.
   - Enforced explicit blocker behavior for absent/invalid M0 (`s05_m0_release_missing`, `s05_deployment_manifest_invalid`).
   - Implemented precondition validation for:
     - release archive sha256 pin match;
     - deployment-manifest validity and `source_commit` match;
     - required capabilities by profile (supervised requires `runner-readonly`; service requires M1 lifecycle capabilities);
     - existing checkout safety (no dirty tree, no mutable branch, allowlisted origin).
   - Added security blockers for unsafe archives:
     - path traversal;
     - symlink/hardlink entries;
     - special file entries.
   - Implemented release materialization flow:
     - isolated staging extraction under setup cache;
     - full content hash verification from deployment manifest;
     - immutable deploy (no destructive reset/clean);
     - offline `--help` probes for `runner_verify` and `runner_stop`.
   - Added explicit owner gates, including Dockerfile/build risk review:
     - `s05-application-release-reviewed`
     - `s05-source-commit-reviewed`
     - `s05-dockerfile-build-reviewed`

2. **Added Git/release adapter (`setup/src/adapters/git.ts`)**
   - Added existing checkout observation:
     - dirty state, branch/detached head, origin URL, current commit, deployed manifest commit.
   - Added archive inspection:
     - archive hash computation and pin comparison;
     - tar entry path/type validation;
     - deployment manifest extraction + schema validation.
   - Added hash verification for every manifest `content_hashes` entry.
   - Added safe extraction and non-destructive materialization primitives.
   - Added read-only Git commit existence check.
   - Added explicit blocked placeholder for optional private read-only fetch adapter path (not auto-enabled).

3. **Registered S05 stage (`setup/src/core/engine.ts`)**
   - Wired new adapter + stage into static stage registry immediately after S04.

4. **Added integration tests (`setup/tests/integration/application.test.ts`)**
   - trusted synthetic M0 deploy success path;
   - explicit M0 blocker path;
   - unsafe symlink/traversal archive rejection before extraction;
   - dirty checkout refusal with no reset;
   - manifest hash mismatch security failure.

5. **Added S05 documentation (`setup/docs/application-release.md`)**
   - Documented trusted artifact model, preconditions, gates, safety boundaries, and apply/verify behavior.
