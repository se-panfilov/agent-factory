## Реализованное поведение

**Execution/proofs.** Engine передаёт ровно одну operation. Effect event связывает SHA-256 canonical typed receipt с attempt. `verifyOperation` у S02…S05 подтверждает определённые postconditions после durable effect evidence и до verify/checkpoint. Simulation success подтверждает simulation command и dpkg observation, не установку packages. Core единолично пишет state/journal/commit metadata.

После завершённой operation сохраняется snapshot с известным progress; незавершённый journal attempt до binding всё равно блокирует replay. Versioned `completed_operations` содержит config hash, receipt и checkpoint identity и проверяется по journal attempt/stage/operation/sequence/state hash/effect digest. Final `clean_proof` создаётся только после stage-wide verify/observe и matching bound journal; operation completion не объявляет весь stage verified. Metadata-only writes наследуют proof только от exact predecessor без in-flight. Subsequent plan/gate writes не уничтожают его. Failed final publication снимает verified у активного stage; plain status не выдаёт success до повторной проверки.

**Recovery admission.** Общий evaluator вызывается ordinary load и всеми recovery phases, включая markerless/current, start, prepared и cleanup. Он проверяет quarantine, journal uncertainty, manifest/installation/checkpoint/receipt bindings, writer predecessor и immutable decision. Prepared decision содержит exact source manifest плюс candidate hash. Допустим только этот source или определённый restore transition generation+1/hash/timestamp при сохранении остального proof. Если primary уже переименован, но manifest ещё не опубликован, продолжение завершает тот же transition. Новое contradictory evidence блокирует cleanup до удаления marker. Restore не удаляет valid checkpoint/progress proof.

Legacy manifests читаются по прежним exact-generation правилам; legacy exact checkpoint/state proof может пройти markerless recovery. Unknown installation не объявляется fresh. Legacy prepared decision без source-manifest binding сохраняется и блокируется: автоматического удаления/конвертера нет. Старые S03 approvals после расширения reviewed inputs требуют нового плана. Downgrade/чередование writers, не понимающих новую internal metadata, не квалифицированы.

**S03.** Approved input hash сверяется перед intent, повторно перед effect и перед checkpoint; следующий шаг сравнивает свежий observation с предыдущими подтверждёнными postconditions. В hash включены полные reviewed diff/manual inputs, SSH/firewall effective inputs, bounded raw config/drop-ins/UFW/template content и uid/gid/mode/type. Unsafe ownership/symlink/read failure/oversize — fail closed. Bounds: 64 include entries, 256 KiB/file, 2 MiB aggregate. Собственные install/arming transitions не маскируют foreign drift. Console/second-session/Tailscale/cutover acknowledgements и negative-tailnet rollback сохранены. Неполный настоящий host adapter остаётся отдельным Q2 blocker.

**S05.** Общий commit-marker early return удалён. No-op materialize требует собственных content postconditions; probe operation выполняется отдельно. Fresh deploy явно планирует две operation-owned extraction/hash checks; process-local staging cache не используется. Probe receipt привязан к archive SHA/commit. Fresh failure/timeout/missing command не получает verify/checkpoint, зависимый S06 не запускается. Повторный verify/status-refresh/replan проверяет текущие content/commands; explicit verify failure снимает recorded verified. Исполнение существующего checkout при plan/refresh требует journal-bound reviewed deployment receipt; один marker не запускает untrusted code до gates. Plain status/gate diagnostics читают recorded data без запуска процессов и сохраняют возраст evidence. Manifest/profile capabilities, hashes, traversal/symlink/build checks сохранены.

**S04.** Relogin prerequisite не переименован в approve-able gate: он убран из approvals и проверяется наблюдением перед operation, которой нужна active session. Reviewed package/config/restart/group actions выполняются до этой границы. Подтверждённый account group effect получает durable receipt/checkpoint, затем existing public `awaiting_manual`, exit 4, in-flight=null. `id -nG USER` и `id -nG` различают account database и running process. Resume re-observes pins/config/ownership/session и использует journal/config-bound progress; не выводит ownership из operation ID/старого planned flag. Unmanaged matching install, foreign workloads/context, unsafe socket/TCP API остаются blocked.

**Inventory.** Полный S00…S14 inventory содержит actual kinds/resources/effects/receipts/gates/capabilities/no-op/routes. S09/S10/S12/S13 generic closure включает запрещённый S08; они намеренно не объявлены supported CLI routes. S08/S14 containment сохранён. Будущие квалифицируемые dedicated proposal/service/private-infra/collector entrypoints обозначены без обхода S08. Обязательный S00…S07 не закрыт новым глобальным запретом.
