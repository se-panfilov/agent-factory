## Implemented behavior (P04 scope)

1. **New stage S03 (`access`) with deterministic stage API flow**
   - Added `observe -> plan -> apply -> verify -> recover`.
   - Observation captures access-critical signals: provider-console/second-session evidence, tailscale login state, explicit IPv4+IPv6 exposure checks, sshd/firewall diff previews, rollback readiness/armed state.
   - Planning binds operations to an observation hash and explicit tailscale pin precondition.

2. **Manual gates and cutover controls**
   - Added required gate set for:
     - owner-confirmed provider console
     - independent second login + sudo
     - tailscale login confirmation
     - explicit sshd/firewall diff review
     - firewall cutover approval
     - post-cutover acknowledgement
   - `apply` rejects execution when mandatory evidence is absent (no silent approval).

3. **Staged change + rollback timer + safe failure**
   - Apply sequence models: tailscale pin install → diff stage/sshd validation → rollback arm (10 min) → cutover → private-tailnet verification → rollback disarm after independent ack.
   - If failure occurs after arming/cutover, stage triggers rollback attempt.
   - Rollback failure escalates to recovery-required (`exit 8` path), preventing success-shaped completion.

4. **Template and recovery documentation**
   - Added minimal ssh/firewall/systemd templates for managed S03 artifacts.
   - Added `setup/docs/access-recovery.md` with gate requirements, marker evidence contract, rollback semantics, and mutation safety switch.

5. **Default adapter safety guard**
   - Node adapter reads deterministic manual evidence markers from setup state.
   - S03 mutations are blocked unless explicitly enabled with `FACTORY_SETUP_ALLOW_S03_MUTATIONS=1`, preventing accidental network changes on non-disposable hosts.
