## Lock invariant and atomic transitions

`lock/owner.json` binds installation, boot, PID, safe start ticks, UUID nonce and creation time. Strict bounded UTF-8 JSON rejects duplicates, arrays, unknown fields, null ticks and unsafe file metadata. Real proc-stat parsing starts after the final closing comm parenthesis. Only ESRCH proves PID absence; EPERM/read failures are unknown. PID reuse and boot change require resource reconciliation; neither is automatic proof that descendants/containers ended.

Every cooperating acquire, release, recovery and cancel publisher obtains `lock-protocol/` through atomic mkdir on a recognized local filesystem. All generation checks and mutable-path rename/remove execute while that mutex is held. Installation-lock mkdir publishes one generation; quarantine rename moves only that generation; release removes only its full matching generation. No participant can acquire a replacement between check and transition. This is a short protocol mutex, not another installation/run lock. Consumers only observe cancellation and cannot mutate generations.

Contention returns typed exit7. Guard publication failure preserves the partial guard; it cannot be automatically reclaimed, even if its participant PID vanished. Manual inspection is intentional. Acquisition identity is checked before installation-lock mkdir. Owner write/fsync failure leaves the partial installation lock. Release failure/unknown cleanup becomes exit8. This protocol handles cooperating writers; hostile same-UID/root writers and full filesystem isolation remain Q2.

Before quarantine, recovery validates installation, committed state/clean candidate, exact journal receipt/checkpoint bindings and absence of unresolved operations. A resolved historical journal is not a live operation. Resource-bearing S03/S04/S05/S08/S09/S10/S12/S13 state, boot change or PID reuse still requires a resource reconciler/manual action. The pass does not invent one. Unknown filesystem semantics block. APFS/HFS are development-only; initial production qualification remains Ubuntu24 amd64 on supported local storage.

Quarantine uses a fresh UUID name; cooperating participants cannot collide or overwrite it. Failed rename retains the source; failure after rename retains quarantine. Parent fsync failure reports unknown durability, not a rollback or success. Temp/guard/quarantine evidence is retained on publication failures. Injected I/O failures do not qualify physical power loss.

## Cancellation

CLI normal cancel/recover and direct emergency enforce the configured ordinary owner. Normal cancel does not take the installation lock: it takes only the short protocol mutex, reads its full generation and publishes `cancel-request.json` schema2 `{schema_version:2,owner:<full LockOwner>}`. No active/valid lock means no cancellation publication. Every caller must supply the same explicit ProcessAdapter as its engine/run, including helpers and child/standalone runners. There is no omitted-adapter or actual-UID fallback; production CLI root refusal is unchanged.

A unique private temp directory reserves a publication payload. Write, file fsync, atomic rename and parent fsync precede success. Failed repeated publication cannot damage the already accepted matching request. A failure after rename is an unknown durability result and retains matching bytes. Writers and lock-generation transitions serialize; consumer is read-only, so it cannot delete a newer unread request. Observations never remove accepted cancellation. Repeated reads are idempotent. A future run has a new full generation and ignores the old request. Only the exact known legacy shape (requested_at, installation_id, target_lock_nonce, target_lock_pid, target_lock_boot_id; all targets null or fully typed) is recognised without schema_version. It grants no cancellation authority. Only lstat ENOENT counts as absence; permission/read errors and broken symlinks fail closed. Schema2 is decoded/strictly validated before comparing full owner generation. Missing/extra/wrong-type fields and unknown versions are cancel_evidence_unknown8, with no intent/effect and the file preserved. Valid foreign/stale generations are no-ops; arbitrary non-v2 JSON is never treated as legacy.

Final effect admission runs all existing long policy/context reads and bounded reseal first, then reads cancel, then executes the existing metadata fence, synchronous TTL and gate checks. A nonmatching cancel read cannot reopen the R221 context window. Matching cancel before a new intent has no next effect. Matching cancel after a checkpoint retains that exact receipt/checkpoint; explicit resume admits only the remaining suffix. If an operation is in flight, a claimed signal exit without a durable safe boundary becomes exit8. Confirmed between-operation cancellation is130; process-tree TERM/KILL supervision remains Q1B. No apt/dpkg killing is implemented here.

## Emergency trust

Emergency uses no installation lock, plan or fresh gate. Ordinary owner is required before PAUSED or command effects. Only schema-valid current supervised deployments with an exact config/release/manifest S05 receipt and matching journal publication qualify. The current archive, manifest, entrypoint/content and safe path metadata are checked again. No help receipt replaces byte verification. Shared S05 preparation confines Node entrypoints to the release; emergency excludes direct executables, shell/eval, arbitrary absolute programs, traversal arguments and symlink escapes. cwd is the checked deployment root. Node is the current installed pin: bootstrap prefix/version/archive pin, version lock and actual running executable bytes must agree. On Linux `/proc/self/exe` identifies those running bytes independently of pathname replacement; final file witnesses guard subsequent dispatch. There is no persistent trust cache.

PAUSED publication is durable atomic control publication. Stop failure/timeout/output truncation keeps PAUSED and returns8. A declared `app_status` command is used only with `app-status`; the narrow adapter accepts JSON `{status:"stopped",installation_id:<exact UUID>}` as its postcondition. No new command is synthesized. Missing postcondition capability reports attempted/unconfirmed stop (8). Service stop is unsupported (5). Existing M0 manifests without status therefore cannot claim a confirmed stopped outcome.

Every supported supervised S05 deployment depends on S04 Docker. This supplies the obligation for fixed-identity live Docker discovery even when advisory inventory is absent, empty, stale or unusable. No Docker-free S05 deployment proof/profile currently exists: unavailable Docker returns8/manual reconciliation, never an automatic installation or sudo fallback. Advisory inventory status is recorded, but its bytes never select argv/resources or waive discovery. Live inventory uses the fixed installation label, validates unique hex IDs, then checks full JSON identity/ownership/running state. Known foreign UUID ownership is skipped; absent/malformed inspection, timeouts and truncation are unknown, never foreign. Each owned stop needs a stopped postcondition. Returned failures and rejected process/FS/admission boundaries share a typed emergency outcome. After publication/attempted effects, unknown or partial cleanup returns8, with safe manual-recovery action and attempted/confirmed/unknown resources in envelope.data.emergency_outcome. Confirmed prefix entries are added only after status/post-inspect. PAUSED reports prior presence, observed existence, not_published/published_unconfirmed/durable publication and prior preservation; existence alone is not durability. Publication hooks record rename/file/parent sync phases without changing the cancel writer protocol. No rollback, deletion, automatic retry or unpause occurs. Fake daemon tests qualify this adapter contract only; real Docker/host boundary is NOT RUN.

Repeat recovery preserves that result. Committed metadata never becomes prepared-to-committed through recovery; resume still applies exact review/context/policy/session/TTL/gate admission. Recovery0 reports state consistency only, `resume_authorized:false`, `admission_required:true`.
