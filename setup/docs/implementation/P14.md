## Implemented behavior (P14 scope only)

1. Added **S14 stage** with deterministic `observe → plan → apply → verify → recover`, dependency `S07`, owner gate `s14-update-owner-approved`, and explicit app capability requirements (`app-pause/app-stop/app-status/app-migrate/app-recover`).
2. Added **update manifest contract** (`s14-update-manifest.json`) with strict validation:
   - pinned immutable app release (`commit_sha`, `release_dir`, `immutable=true`);
   - installer/state schema compatibility range checks + refusal of future schema;
   - owner approvals for release trust, policy diff, permissions diff, migration;
   - explicit command argv for pause/drain/offline_smoke/migrate/restart_paused;
   - hard block on `git pull`, floating `latest`, and bundled OS/Docker/model updates.
3. Added **pre-update safety and compatibility checks**:
   - mandatory verified backup by `backup_id` before mutation;
   - refusal on receipt/current drift before any new side effects;
   - PAUSED marker persistence before, during, after update.
4. Added **atomic switch + immutable old release behavior**:
   - `current` symlink update via temp symlink + atomic rename;
   - previous `current` target preserved and recorded in receipt;
   - no destructive cleanup of previous release.
5. Added **crash/recovery reconciliation path**:
   - if `current` already points to new release but receipt is missing, S14 writes receipt and adopts state without replaying migration.
6. Added **paired rollback/recovery**:
   - on post-migration/post-switch failure, attempt rollback to previous `current` if compatible;
   - otherwise fallback to backup restore only when explicitly allowed by manifest;
   - rollback failure emits exit 8 (`s14_rollback_partial`) and blocks further destructive actions.

## Failure/error scenarios covered in fixtures

- crash boundary: switched `current` with missing receipt reconciled without migration replay;
- rollback boundary: restart failure after switch triggers rollback and keeps PAUSED;
- drift boundary: receipt/current mismatch rejected before mutation (`s14_receipt_current_drift`);
- denied approval: missing policy/permissions approvals blocks apply (`s14_diff_approval_required`);
- duplicate/idempotent run: second apply reuses receipt/current, does not re-run migration.

## Security-sensitive diff

- no `git pull`, no `latest`, no silent mutable source updates;
- no destructive cleanup of previous release or backup artifacts;
- rollback/recovery keeps application paused and refuses unsafe continuation.
