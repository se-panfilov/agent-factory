## Implemented behavior (P05 scope)

1. **New Docker adapter (`setup/src/adapters/docker.ts`)**
   - Added Docker runtime observation model for:
     - exact Docker package candidate/installed versions;
     - visibility of official Docker apt repo candidates;
     - daemon/client compatibility signals;
     - daemon config state (`/etc/docker/daemon.json`) including symlink/JSON validity and owned log-key hash;
     - local-vs-remote context, rootless mode, firewall backend, socket permissions, TCP API exposure;
     - foreign workload detection and public published ports;
     - CPU/RAM/pids cgroup capability checks;
     - docker-group membership and relogin marker.
   - Added mutation API for:
     - installing exact pinned Docker package set;
     - merging owned daemon log keys (`log-driver`, `log-opts`) without touching unknown keys;
     - daemon config validation and restart;
     - docker-group membership update with relogin marker;
     - pinned no-secret fixture run + inspect + cleanup verification.
   - Added mutation guard `FACTORY_SETUP_ALLOW_S04_MUTATIONS=1` to prevent real host mutations by default.

2. **New S04 stage (`setup/src/stages/docker.ts`)**
   - Added deterministic stage flow: `observe -> plan -> apply -> verify -> recover`.
   - Added blocked/manual guards for:
     - unmanaged pre-existing Docker install;
     - foreign containers;
     - conflict packages;
     - invalid/symlink daemon config;
     - remote context/rootless mode;
     - unsupported firewall backend (`nftables`);
     - missing official repo candidates.
   - Added gates:
     - `s04-sudo-docker-install`
     - `s04-docker-daemon-config-diff-reviewed`
     - `s04-docker-daemon-restart-approved`
     - `s04-docker-group-root-equivalent-ack`
     - `s04-docker-group-relogin-required` (conditional)
   - Added explicit relogin-required failure path after docker-group mutation.
   - Added no-public-Docker-API and socket safety checks during apply/verify.
   - Added fixture hardening verification for `read-only`, `cap-drop ALL`, `no-new-privileges`, CPU/RAM/PIDs and ownership labels.

3. **Registry wiring**
   - Registered S04 in default stage registry after S03 in `setup/src/core/engine.ts`.

4. **Documentation**
   - Added `setup/docs/docker.md` with behavior, gates, safety blockers, mutation guard, and VM qualification scenario.

## Security-sensitive diff summary

- S04 refuses unmanaged Docker mutation and foreign-workload restart.
- S04 enforces local Unix-socket context and blocks remote/default-context mismatch.
- S04 blocks TCP Docker API exposure and world-writable socket.
- S04 treats docker-group as root-equivalent via explicit gate and relogin requirement.
- Daemon config writes are limited to owned log keys only, after JSON/symlink safety checks and pre-restart validation.
- Resource probe requires hardening flags and ownership labels.
