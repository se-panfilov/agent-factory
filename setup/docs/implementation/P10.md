## Implemented behavior (P10 scope)

1. Added **S10 stage** (`setup/src/stages/service.ts`) with dependency on `S09` and service-profile admission.
2. Added **systemd adapter** (`setup/src/adapters/systemd.ts`) for unit observation, verification, install/reload/enable/start/stop, directory preparation, release sync, app command execution, and backup/restore operations.
3. Added **capability gate**: if manifest lacks real `recover/serve/pause/stop/migrate/status` capabilities/commands, stage returns:
   - `exit code 5`
   - `code: capability_missing`
   - `public_message: blocked: capability_missing`
4. Added **M2 security evidence gate**: stage requires verified `m2-security-evidence.json` with PR8/PR9/PR11 mapping + manifest-linked refs; filename-only evidence is rejected with `blocked: capability_missing`.
5. Added **explicit manual gates** in S10 plan:
   - `s10-db-migration-approved`
   - `s10-service-enable-approved`
6. Added **backup + migration + rollback** flow:
   - pause command before migration,
   - paired SQLite backup before migrate (when DB exists),
   - call existing app migrator command from manifest (`app_migrate`),
   - on failure: stop service, restore paired backup, run recover command,
   - no automatic unpause.
7. Added **systemd unit template** (`setup/templates/systemd/agent-factory.service`) with:
   - `ExecStartPre` recover,
   - `ExecStart` serve,
   - `ExecReload` pause,
   - `ExecStop` stop,
   - `FACTORY_START_PAUSED=1`.
8. Wired S10 into static registry in `setup/src/core/engine.ts`.
