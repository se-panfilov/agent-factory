## Implemented behavior (P03 scope)

1. **New apt adapter with bounded privileged operations**
   - Added `NodeAptAdapter` with strict command paths and `shell=false` execution.
   - Added apt security options and lock timeout (`DPkg::Lock::Timeout=120`).
   - Added explicit refusal paths for unsigned metadata and interrupted dpkg state.
   - Added read-only observation for sudo availability, metadata freshness, reboot marker, candidates, installed versions, and `dpkg --audit`.

2. **New stage S02 (`system`)**
   - Added `createSystemStage` with contract flow: `observe -> plan -> apply -> verify -> recover`.
   - Stage plans exact apt pins from observed candidates and binds them with `apt_package_set_hash`.
   - Stage requires sudo gates (`s02-sudo-apt-update`, `s02-sudo-apt-install`) for root mutations.
   - Apply re-observes package set; if candidate set changed since approved plan, it refuses and requires renewed plan/gate.
   - Apply runs apt simulation before install and refuses unsafe/auto-repair behavior.
   - Verify enforces pinned installed versions, clean `dpkg --audit`, and surfaces reboot-required as manual action (no auto reboot).

3. **Engine and stage context integration**
   - Registered `S02` in default stage registry after existing stages.
   - Extended `StageContext` with `profile` so stage logic can apply profile-specific allowlist safely.
   - Wired context propagation in planning/apply/status/verify code paths.

4. **Documentation**
   - Added `setup/docs/system.md` describing allowlist, gates, lock handling, refusal rules, and reboot behavior.

## Failure cases covered by tests

- package-set drift between plan and apply (`s02_package_set_changed`, manual action)
- dpkg audit not clean before apply (`s02_dpkg_audit_failed`, no auto-repair)
- unsafe apt pin input rejected (version sanitization)
- successful metadata-refresh + simulation + install + verify cycle with fake adapter
- apt policy parsing and observation mapping with fake process/filesystem adapters

- No automatic reboot.
- No automatic `dpkg --configure -a`/repair; explicit manual next actions returned instead.
